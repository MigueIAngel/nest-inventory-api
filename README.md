An inventory management REST API built with **NestJS** and **TypeORM**. It manages suppliers, products and stock movements, with JWT authentication, role-based access control and a dashboard endpoint.

The companion admin panel built with Angular is available at [angular-admin](https://github.com/MigueIAngel/angular-admin).

**Live demo:** [Swagger UI](https://nest-inventory-api-demo.onrender.com/docs) · [Angular admin panel](https://angular-admin-demo.onrender.com) (log in with `admin@inventory.dev` / `admin123`).

> Hosted on Render's free plan: the first request after a period of inactivity can take up to a minute while the service wakes up. Demo data is reset on every restart.

## Features

- **Modular architecture**: one Nest module per domain (auth, users, suppliers, products, movements, dashboard, seed)
- **JWT authentication** with a global guard, `@Public()` opt-out and a `@CurrentUser()` decorator
- **Role-based access control**: `admin` manages the catalog, `staff` can read it and register stock movements
- **Transactional stock movements**: stock is updated inside a DB transaction with a row lock (`SELECT ... FOR UPDATE`) on PostgreSQL, so concurrent requests cannot oversell. Movements that would leave negative stock are rejected.
- **Search, filters, sorting and pagination** on products (by name/SKU, supplier, low stock)
- **Dashboard summary**: totals, inventory value, low-stock alerts and a 7-day in/out series
- **Validation** with `class-validator` DTOs and a global `ValidationPipe` (whitelisting enabled)
- **OpenAPI docs** generated by the Swagger CLI plugin, with no manual `@ApiProperty` needed
- **Demo data seed** on first boot
- **Tests**: unit tests plus an e2e suite running the whole app against in-memory SQLite
- **CI**: lint, tests, a smoke test against real PostgreSQL and a Docker build

## Getting started

### With Docker

```bash
docker compose up --build
```

- API: http://localhost:3000/api
- Swagger UI: http://localhost:3000/docs

### Local development

```bash
npm install
cp .env.example .env
docker compose up -d db        # PostgreSQL on port 5434
npm run start:dev
```

To try the API without PostgreSQL, set `DB_TYPE=sqlite` and it runs on an in-memory database.

## API overview

All routes are prefixed with `/api` and require a bearer token unless noted.

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/auth/register` | public | Create a staff account |
| `POST` | `/auth/login` | public | Get an access token |
| `GET` | `/auth/me` | any | Current user |
| `GET` | `/users` | admin | List users |
| `GET` | `/suppliers?search=&page=&limit=` | any | List suppliers |
| `POST` `PATCH` `DELETE` | `/suppliers/:id` | admin | Manage suppliers |
| `GET` | `/products?search=&supplierId=&lowStock=&sort=&order=` | any | List products |
| `POST` `PATCH` `DELETE` | `/products/:id` | admin | Manage products |
| `GET` | `/movements?productId=&type=` | any | Movement history |
| `POST` | `/movements` | any | Register an `in`/`out` movement |
| `GET` | `/dashboard/summary` | any | Dashboard metrics |

## Project structure

```
src/
├── auth/          # JWT login/register, guards, decorators
├── users/         # User entity, roles
├── suppliers/     # Suppliers CRUD
├── products/      # Products CRUD, filters
├── movements/     # Transactional stock movements
├── dashboard/     # Aggregated metrics
├── seed/          # Demo data on first boot
├── common/        # Base entity, pagination, transformers
└── config/        # Database and Swagger setup
test/              # e2e tests
```
